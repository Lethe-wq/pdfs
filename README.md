# 页序 · 本地 PDF 工作台

在浏览器里合并、重排、提取和拆分 PDF 页面。中文界面，无需账号或后端，文件读取、预览和导出均在浏览器内完成。

![页序工作台界面](docs/images/workspace.jpg)

## 功能

- **多文件合并**：继续添加 PDF，按最终页面顺序生成一个文件。
- **页面整理**：复选框、Shift 连选、范围选页、多选拖动、旋转、删除和放大预览。
- **整份文件移动**：移动来源文件当前保留的全部页面；已打散的页面会重新聚拢，保持当前相对顺序。
- **三种导出**：导出全部、选中页面另存、按范围拆分并打包 ZIP，可自定义文件名。
- **PDF 转 Word**：将全部或选中页面按整理后的顺序转成可编辑文字 `.docx`，先提取文字层，无文字页可用中英文 OCR，并逐页核对修改。
- **撤销与重做**：保存最近 60 次操作，支持删除、旋转、移动和移除文件。
- **任务控制**：显示处理进度，支持取消；Worker 故障后自动尝试恢复一次，并提供手动重试。

## 快速开始

准备 Node.js **22.13+**（推荐 **24 LTS**）和 **pnpm 11**。

```sh
git clone https://github.com/Lethe-wq/pdfs.git
cd pdfs
pnpm install --frozen-lockfile
pnpm build
pnpm preview
```

打开 **http://127.0.0.1:4173/**，在启动服务的终端按 **Ctrl+C** 停止。

macOS / Linux 也可以在项目目录运行：

```sh
./start.sh
```

脚本会检查依赖、构建项目，并在 **http://127.0.0.1:5173/** 提供生产版本。默认只监听本机；端口被占用时请先停止占用它的服务。

首次安装依赖需要网络。安装完成后，本地启动和 PDF 操作无需连接外部服务。

## 使用方法

1. 添加一个或多个 PDF，新文件按原始页序追加到末尾。
2. 在页面区选择、旋转、删除或移动页面。卡片显示当前页码、来源文件和原始页码。
3. 选择导出方式，修改文件名并生成文件。若自动下载没有出现，点击生成后的下载链接。

### 选择与移动

- 输入 `1-3,5,8-10` 按**当前整理后的页码**选择，替换之前的选择；也支持中文逗号。
- 使用复选框、Shift 连选或全选。拖动选中页的手柄会移动整组选中页面，保持它们的相对顺序；拖动未选中页只移动该页。
- 拖动左侧文件手柄到页面区插入位置，可移动该文件的全部保留页面。页面和文件也提供“移至开头／末尾”按钮。

### 按范围拆分

每行填写一个连续范围或单页，每行生成一个 PDF，最后统一下载 ZIP。例如：

```text
1-3
4-6
8
```

范围使用当前页码，拒绝越界、倒序和重叠；可以跳过页面，界面会显示未包含的页数。只有全部结果生成成功后才提供下载。

### 文字检查、OCR 与 Word

1. 点击“转 Word”或“可搜索 PDF”，选择全部／选中页面，填写输出文件名。
2. 点击“检查／继续检查”。检查结果按稳定页面 ID 保存，切换范围不会清空已有结果。
3. 无文字页点击“继续识别／重试失败页”；有乱码文字层的页面也可单独运行 OCR。中英文模型首次加载需要一些时间。普通识别未发现文字时，会再尝试稀疏文字模式。
4. 对照原页逐行修改，点击文字行会高亮原位置；每页分别确认“已核对”。修改会取消该页确认。可以指定新段落、正文、标题或列表。
5. 无文字／失败页必须逐页确认不使用文字。Word 跳过这些页，至少保留一页文字；可搜索 PDF 保留这些原页，不添加文字层。
6. 点击生成按钮；自动下载没有出现时使用工作区中的下载链接。

OCR 成功页立即保留；取消、单页失败和关闭弹窗不会清空已完成结果及校对。可继续未完成任务、只重试失败页，或明确重新识别某页。重新识别成功前保留旧结果；替换已有 OCR 修改需要确认。

Word 默认 A4、常规页边距、11 磅正文，保留源页之间分页。依据位置和段落关系保守合并换行，支持基本标题和 Word 原生列表；勾选“按原行分段”可关闭合并。文字可能重新流动，不保证 Word 页数与 PDF 一致，也不恢复图片、表格结构、公式、多栏和原字体。Word 不应用整理区旋转，不更新完整 PDF 生成基准。

### 可搜索 PDF

保留原始页面的可见内容、尺寸和整理后的顺序与旋转；只对无原文字层且已核对的 OCR 页面添加不可见文字。校对修改用于新文字层，搜索高亮以原行框为准。已有文字层继续保留，本轮不修复或替换乱码文字层。

全部页面没有可用文字时，可逐页确认生成原页保留版，界面会提示本次没有新增可搜索文字。所有页面生成成功后才提供下载，取消或失败不下载部分结果。完整范围导出可更新 PDF 生成基准，选中导出不更新。

### 本机草稿保存

“保存在此浏览器”默认关闭。开启后通过 IndexedDB 保存原 PDF、当前排列及旋转、文字结果、逐行修改和核对状态；原 PDF 只写入一次，后续保存更新元数据。界面显示保存状态，存储失败仍可继续会话内操作。

刷新后选择“恢复草稿”或“删除草稿”。恢复不包含撤销历史、运行中的任务或旧下载链接；未完成任务需手动继续。关闭保存会删除已有缓存但保留当前会话；“清空工作区及缓存”同时清空两者。不同浏览器、本地地址和线上站点的草稿互不共享；浏览器清理数据后不能保证恢复。

### 快捷键

| 操作 | macOS | Windows / Linux |
| --- | --- | --- |
| 全选页面 | `⌘ A` | `Ctrl A` |
| 撤销 | `⌘ Z` | `Ctrl Z` |

## 隐私与使用边界

- **原始文件不会被改写或上传**。项目没有上传接口；PDF、OCR 模型、字体、CMap、WASM 和 Worker 均从本地或同源静态资源加载，不使用 CDN、远程字体或分析脚本。
- 未开启本机保存时，工作区保存在当前会话；未导出的 PDF 修改、文字草稿、未落盘修改或运行中的任务会触发离开提示。选页另存、拆分和 Word 不更新完整 PDF 生成基准。
- “已生成，可下载”表示文件已生成，不代表已经保存到磁盘，请确认浏览器下载结果。
- 取消批量导入会保留已完成验证和预览读取的文件。取消导出会保留工作区及上次生成的下载链接，不提供部分结果。
- Worker 意外停止或连续 120 秒无响应时，任务自动尝试恢复一次。恢复通过当前会话的原始 File/Blob 引用重新读取来源，保留排列、旋转和撤销历史；再次失败可手动重试。
- Word 检查复用现有 PDF.js 文档；Word Worker 故障后使用文字快照自动重试一次，仍失败可以重新检查和生成。取消会停止调度后续页面并终止当前转换 Worker。OCR 逐页渲染和识别，单页画布限制最长边 3500 像素及约 800 万像素；结束或取消会释放识别引擎，不保存原始图像。
- 支持普通 PDF，保留各页原有尺寸、文字和矢量内容。**加密 PDF 暂不支持**；损坏、加密或零页文件会给出错误，不影响已导入文件。
- **不保证保留书签、交互表单和数字签名**。当前不提供压缩、PDF 正文编辑、持久化历史或云端存储。
- 优先支持桌面浏览器。已验证 100 页、约 30 MB 的扫描件；OCR 引擎另已测量同规模样本，浏览器和 Safari 的具体测试范围见验证说明；没有设置硬性页数或大小限制，更大文件的承载能力取决于设备内存。

## 开发与检查

```sh
# 开发模式：http://127.0.0.1:5173/
pnpm dev

# 单元测试
pnpm test

# TypeScript 检查与生产构建
pnpm build

# 运行真实生产 Worker 的恢复与取消检查（需要 Node.js 24+，先构建）
pnpm test:worker

# 真实 Word Worker：检查、生成、崩溃重试及取消后重新生成
pnpm test:word-worker

# 真实可搜索 PDF Worker（需先启动 pnpm dev）
node scripts/verify-searchable-worker.mjs

# OCR 坐标、PDF 中文文字层及 DOCX XML
node scripts/verify-text-workflow.mjs /path/to/local.pdf

# 真实 OCR 引擎（Node.js 24+，本地无文字层 PDF；结果写入 tmp/，不上传）
node scripts/verify-ocr.mjs /absolute/path/to/local.pdf
```

开发模式使用本机 Vite 热更新连接。`pnpm build` 会将 PDF.js 预览资源、Tesseract OCR 引擎和中英文模型复制到本地并生成 `dist/`；构建产物可以部署到静态网站托管服务，当前仓库没有自动部署配置。

## 项目结构

技术栈：**React + TypeScript + Vite**、[PDF.js](https://mozilla.github.io/pdf.js/)、[pdf-lib](https://pdf-lib.js.org/)、[dnd-kit](https://dndkit.com/)、[JSZip](https://stuk.github.io/jszip/)、[docx](https://github.com/dolanmiu/docx) 和 [Tesseract.js](https://github.com/naptha/tesseract.js)。

来源文件与页面排列分开管理：每个页面实例使用稳定 ID，记录来源 ID、原始页索引和旋转角度；当前页码随排列计算。原始字节保存在处理 Worker，主线程保留会话内 File/Blob 引用以供恢复。

| 模块 | 职责 |
| --- | --- |
| `src/App.tsx`、`src/components.tsx` | 界面编排、页面卡片、来源列表与弹窗 |
| `src/model.ts` | 页面模型、范围解析、群组移动和历史 |
| `src/use-workspace.ts`、`src/use-selection.ts`、`src/use-page-drag.ts` | 工作区、生成基准、选择与拖动 |
| `src/use-task.ts`、`src/use-import.ts`、`src/use-export.ts`、`src/use-recovery.ts` | 任务进度、取消、导入、导出与恢复 |
| `src/pdf-protocol.ts`、`src/pdf-client.ts` | 类型化 Worker 通信、超时与重试 |
| `src/pdf.worker.ts`、`src/pdf-engine.ts` | PDF 验证、批量复制页面、生成 PDF 和 ZIP |
| `src/PdfCanvas.tsx`、`src/preview.ts`、`src/visibility.ts` | 按需预览、渲染并发控制和资源释放 |
| `src/WordModal.tsx`、`src/use-word-export.ts` | 共享文字校对、逐页检查／OCR 进度、确认及 Word／搜索 PDF 下载 |
| `src/word-check.ts`、`src/word-text.ts` | 逐页提取、坐标合并文字行与无文字页清单 |
| `src/word-protocol.ts`、`src/word-client.ts`、`src/word.worker.ts`、`src/word-engine.ts` | 独立按需加载的 Word Worker、取消、超时重试和 DOCX 生成 |
| `src/ocr-render.ts`、`src/ocr-pages.ts` | 逐页受限画布、无文字页识别及顺序合并 |
| `src/ocr-client.ts`、`src/ocr.worker.ts`、`src/ocr-engine.ts` | 按需 OCR Worker、中英文模型、取消、进度和单次重试 |
| `src/text-drafts.ts`、`src/text-layout.ts`、`src/OcrPreview.tsx` | 页面草稿、坐标映射、段落与原页对照 |
| `src/draft-storage.ts`、`src/use-draft-storage.ts` | IndexedDB 保存、恢复、迁移及写入状态 |
| `src/searchable-pdf.ts`、`public/fonts/` | 不可见文字层、中文字体子集及许可证 |
| `scripts/`、`tests/` | 资源准备、测试样本、导出检查与 Worker 验证 |

缩略图按需渲染并限制并发，卡片共享可见性观察器。导出按来源批量复制页面以复用字体和图像资源，完整输出 buffer 直接转移；历史记录不再引用的来源及预览资源会释放。

## 验证记录

截至 **2026-10-11**：99 项自动测试、TypeScript 检查和生产构建通过；真实 PDF／Word Worker 的崩溃恢复、取消及后续生成检查通过。内置浏览器完成中英文混合 PDF 的 Word 实际下载，DOCX 内部 XML 和 macOS 文本读取器确认文字、顺序及源页分页符正确。Safari 文字读取兼容修复通过真实 PDF 回归：缺少流的异步遍历接口时仍可逐块提取文字，取消和超时后释放读取资源。

内置浏览器完成合并 PDF、选中 PDF 和拆分 ZIP 的实际下载；Safari 完成两文件整理及合并下载。输出经独立 PDF 读取器核对页序、内容、尺寸和旋转，并在 macOS“预览”中打开。100 页、29.12 MiB 扫描件导入、预览与下载成功，输出的全部扫描图像哈希与原文件一致。

OCR 另用本地 3 页转曲 PDF 验证：3 页均识别出文字，空白页不产生正文，生成的可编辑 DOCX 页序与分页符正确。本地生产构建另在内置浏览器完成 OCR、文字修改、确认和实际 Word 下载，以及取消后保留检查结果和下载链接。识别仍有少量错字，需人工核对；此记录不等同于 Safari 端到端验收。
