# 验证说明

## 本轮：OCR 草稿、校对、可搜索 PDF 与 Word 排版（2026-10-11）

以下为本轮结果。后文保留早期验证记录；早期关于弹窗清除状态、100 页 OCR 未验收及应用安装情况的记录不代表本轮状态。

- 99 项测试通过，TypeScript 与生产构建通过；原 PDF、Word、可搜索 PDF 三种真实生产 Worker 检查通过，覆盖崩溃后恢复并重试、取消后复用和文字／页序／旋转。
- 草稿测试覆盖 IndexedDB 原始 Blob、当前页序及旋转、校对修改和核对状态的往返保存，处理中状态恢复为待处理、关闭保存删除缓存、不可用存储报错及延迟写入。原 PDF 存入独立对象仓库一次，逐页进度仅更新元数据，避免每识别一页重写大文件。
- 工作流测试覆盖关闭／重开与范围切换保留草稿、单页失败继续其他页并只重试失败页、取消保留已完成页并忽略迟到结果、移动后的当前页码、删除后撤销复用结果、无文字明确确认保留原页、Word 禁止生成空正文。
- 可搜索 PDF 测试用真实中文字体和 PDF.js 提取；覆盖中英文及标点、校对后文字、混合纸张、非零 CropBox、0／90／180／270 度旋转及原生文字坐标映射。输出与原页的栅格像素逐像素相同，新增不可见文字可以被读取；不支持的字体字符会使整次导出失败，不返回部分文件。
- 倾斜英文扫描样本经过真实 OCR 自动纠偏，逆变换映射回原图，人工查看行框叠加结果；另有纠偏角度符号的坐标回归测试。行框搜索位置不承诺修改后逐字精度。
- DOCX XML 验证可编辑文字顺序、保守段落合并、手动标题、原生列表、源页分页与按原行输出。默认 A4、11 磅正文。标题、列表恢复属于基本排版，未验收表格、公式、多栏和原字体恢复。

### 本地浏览器实际操作

内置浏览器导入用户指定的 3 页 PDF，检查原文字层为空，完成 OCR。修改第一行、指定一级标题并逐页操作核对开关；实际下载可搜索 PDF 和 DOCX，独立读取确认校对文字、PDF 页数、Word 标题与两个源页分页符。开启本机保存后刷新，出现恢复提示，恢复原 PDF、文字修改和核对状态，无需再次 OCR。关闭弹窗后再次打开可复用结果。桌面左右对照和窄屏上下布局均已查看，点击文字行的原图框位置正确。

这些操作验证校对机制，不代表已替用户核对全文；原识别结果仍有错字。用户 PDF、下载内容和截图仅位于本机，不进入源码或部署包。

### 规模与限制

设备 Apple M5、16 GiB 内存，Node.js 24.19.0。100 页扫描样本 29.12 MiB；Node 单次 OCR → 坐标转换 → 可搜索 PDF → Word 流水线耗时 86.375 秒，进程峰值 RSS 1253.9 MiB。这次测量在新增 PDF.js 页资源 cleanup 前进行，包含测试运行时，不能当作浏览器峰值内存或准确率承诺。样本文字稀疏且带噪声，默认分块无结果时使用稀疏文字识别回退；实际结果存在误识别。

同一 100 页样本在内置浏览器完成导入、文字检查和全部 100 页 OCR，页面切换与校对结果可用。本轮没有取得可信的浏览器全程耗时与峰值内存，也没有逐页人工核对这个压力样本。用户 3 页文件的 Node 文字流水线约 3.1 秒，峰值 RSS 522.8 MiB；两种样本不可直接比较。

## Word 引擎规模检查

100 页、29.14 MiB 样本在扫描图像上叠加每页可搜索文字。Node.js 24 隔离进程逐页使用 PDF.js 提取，再调用与浏览器相同的文字整理和 DOCX 生成代码：单次检查 96 ms，生成 20 ms，进程峰值 RSS 250.6 MiB。输出 XML 包含顺序正确的 100 个可编辑文字段落和 99 个源页分页符。

这是引擎测量，不包含浏览器、缩略图和 Worker 通信，不能作为浏览器响应速度或内存上限的承诺。可使用自己的含文字样本复测：

```sh
mkdir -p tmp/pdfs
node scripts/benchmark-word.mjs /path/to/100-page.pdf
```

报告和 DOCX 写入 `tmp/pdfs/`；全部无文字时只写报告，不生成空 DOCX。
